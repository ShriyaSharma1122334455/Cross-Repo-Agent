- T01: project skeleton — `pyproject.toml`, `.env.example`, `docker-compose.yml` (agent + dynamodb-local stub), `src/blast_radius/__init__.py`. Verified `pip install -e .`, `import blast_radius`, and `pytest` (0 tests) all succeed.
- T02: `src/blast_radius/config.py` — `Config` dataclass loading from env, with required vars (`GITHUB_APP_ID`, `GITHUB_APP_PRIVATE_KEY_PATH`, `GITHUB_WEBHOOK_SECRET`, `TARGET_ORG`) raising `ConfigError` when missing, and defaults for model tiers, AWS region, confidence threshold, and state backend.
- T03: `src/blast_radius/models/` — plain dataclasses for `ChangeContract`/`SymbolChange` (`change.py`), `ConsumerCandidate`/`CallSite` (`consumer.py`), `Verdict`/`ReasoningTrace`/`Citation`/`Confidence` (`verdict.py`), and `RunResults`/`ConsumerResult`/`ActionRecord` (`run.py`). All frozen, stdlib-only imports (`dataclasses`, `enum`), no I/O. Verified every model constructs, is immutable, and the package has zero imports from `tools/`, `github/`, `state/`, or a model client.
- T04: `src/blast_radius/parsing/` — `LanguageAnalyzer` ABC (`interface.py`) defining `find_imports` (local names a package is bound to in a file, handling aliasing) and `find_call_sites` (call sites of a symbol given those local names), the pluggability seam for a future second language. No concrete logic; imports only `abc` and `blast_radius.models.CallSite`, nothing from `tools/` or a model client. Verified it can't be instantiated directly and both methods report as abstract.
- T05: `src/blast_radius/parsing/typescript.py` — `TypeScriptAnalyzer` implementing `LanguageAnalyzer` via tree-sitter + tree-sitter-typescript, plus `queries/imports.scm` and `queries/call_sites.scm`. Covers both ES module imports (named/aliased/default/namespace) and CommonJS `require()` (destructured, renamed, or bound to a whole-module variable), since consumer fixtures use CommonJS. Per call site, extracts file/line/snippet, `args_passed`, `return_consumed` (bare/awaited expression-statement calls are discarded; assignment, return, or use as another call's argument counts as consumed), and `surrounding_context` ("inside try/catch", or "followed by a branch checking `<var>`" when the next sibling statement is an `if` referencing the assigned variable). Verified against the real `checkout-service`/`billing-worker`/`reporting-api` fixtures (correctly distinguishing the no-branch vs. null-check-then-retry call sites that drive their different verdicts) plus synthetic cases for discarded returns, try/catch, aliasing, and namespace-style `require`. Empty source/no-match returns `[]`, never an error. Zero model-client or `tools/` imports.
- T06: `tests/conftest.py`, `tests/unit/test_call_sites.py` — unit tests covering plain call, call with args, discarded return, consumed return, try/catch, null-check branch, aliased import, and no-import/empty-source cases; plus an AST-based static-analysis test asserting nothing under `parsing/` imports `strands`, `anthropic`, `bedrock`, or `tools.usage_analysis`. Verified the guard test actually fails when a forbidden import is injected (tested with a real `strands` import, then reverted) rather than trusting it by inspection alone. All 10 tests pass.
- T04 (correction): `LanguageAnalyzer.find_imports` gained a required `symbol` parameter (was `package` alone) — the original signature couldn't disambiguate which of several symbols imported from the same package a given local name belonged to (e.g. `const { charge, getTransactionHistory } = require("payments-lib")`), which real fixture code exercises immediately. Caught while implementing T05, before anything else depended on the old signature.
- T07 (in progress, paused pending GitHub App creation): `src/blast_radius/github/client.py` — `GitHubAppClient`, a PyGithub wrapper authenticated via `Auth.AppAuth`/`GithubIntegration` per-installation (not a PAT), exposing `get_repo`, `get_pull_request`, `get_file_contents`. Construction and method signatures verified; the live smoke-test against a real PR is blocked on the user creating a GitHub App (no `GITHUB_APP_ID`/private key configured yet).
- T11: `fixtures/` — one provider (`payments-lib`) and four consumer repos proving each verdict path. The PR bundles a signature change (`charge(cardToken, amount)` → `charge(amount, cardToken)`, mechanical) and a return-contract change (decline resolves `null` → throws `PaymentDeclinedError`, semantic) on the same symbol. `checkout-service` never branches on the return value → `mechanically_fixable`; `billing-worker` branches on `null` to trigger a retry → `needs_human`, since the naive arg-order fix would compile while silently making the retry path unreachable; `reporting-api` imports the library but never calls `charge` → `unaffected`; `legacy-admin` pins `payments-lib` to `^1.2.0`, excluding the change → `unaffected` by version constraint alone. `fixtures/setup.sh` (re)creates/resets all five repos and the breaking-change PR on GitHub via `gh`, force-pushing fresh content each run so re-running is idempotent. Verified each consumer's `npm test` passes standalone against `payments-lib@1.2.0`, and `setup.sh`'s git logic (copy → commit → force-push, `v2/` overlay, `node_modules`/lockfile exclusion) against a mocked `gh` + local bare repos, run twice, produces no duplicate commits.
